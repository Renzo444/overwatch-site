Roles and permissions

Every Overwatch Console user has one of three roles: viewer, analyst or admin (shown as Administrator on the Team tab). Roles are cumulative: an analyst can do everything a viewer can, and an admin can do everything an analyst can. Your role is shown in the account menu (your initials, top right).

The server enforces every rule on this page. If a button is visible but your role does not allow the action, the request is refused and you see an error such as "Access Denied" or "Administrator privileges required".

The three roles in short

RoleIntended forIn one line
ViewerStakeholders, auditors, managersReads every page and exports audit records. Cannot run agents, ask Atlas, or change records or settings.
AnalystSOC analysts and engineersRuns agents, works and closes incidents, comments, records reviews and drafts detections. Cannot approve, deploy or change tenant settings.
AdminSOC leads and platform ownersEverything, including approval decisions, deployments, tenant configuration and the team.

Approvals are separate from roles

Having the admin role does not let anything skip the approval gate. Response actions an agent proposes, such as containment, create a request in Approvals, and an admin must approve it. Running an approved response is its own step. Rule deployments, tuning changes and Demitry's incident closes also wait for an admin decision.

An admin chooses, action by action, what runs on its own in Settings > Agent Policies under What runs on its own: Approval, Full auto or Scheduled (full auto outside staffed hours). Today only two actions can run without a person: Demitry closing a false positive, and Maxwell deploying a Renzo detection that passed every review check, up to a daily limit and a total number of kept rules that the admin sets. Even then, each action runs only when its own checks pass: a draft that repeats a live rule is skipped, one that overlaps a live rule waits in Approvals, and retiring one of Maxwell's rules to make room always needs an admin's approval. Rule tunes, Demitry's overrides of Dax and containment always wait for a person. See Autonomy and approvals and Set agent autonomy.

Some actions run straight away because the person is the one deciding: for example an analyst or admin closing an incident, or an admin deploying or recalling a rule from the Detection Library. These are recorded in the Audit Trail.

Adding users and changing roles

Admins manage people in Settings > Team. From there an admin invites a person by email with a role, changes another person's role, and deactivates or reactivates an account. See Invite a teammate.

  • Your organization's first admin is created by the Overwatch team, who send that person a one-time invitation link.
  • You cannot change your own role or deactivate yourself. Ask another admin.
  • The organization always keeps at least one active admin. To demote or deactivate the last one, make someone else an admin first.
  • Every role change is recorded in the Audit Trail with who made it and the old and new role.
  • An invitation starts on the viewer role unless the admin picks another.
  • A role change or deactivation takes effect on the user's next request. They do not need to sign out.
  • A sign-in lasts up to 8 hours.
